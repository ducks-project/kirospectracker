# Screenshots capture guide

This folder holds the images referenced by the project [README](../../README.md). The
`.png` files are not generated by the build; they must be captured from the running
extension. This guide lists what to capture and how, so the images stay consistent.

## Files expected

| File                       | Shows                                                     |
| -------------------------- | --------------------------------------------------------- |
| `dashboard.png`            | The activity-bar dashboard (status, progress bars, stats) |
| `explorer-decorations.png` | Spec folders in the file explorer with status badges      |

## How to capture

1. Build and launch the extension in a development host: open the project in the IDE and
   press `F5` (Extension Development Host), or install the packaged `.vsix`.
2. Open a workspace that contains several `.kiro/specs/<name>/` folders in different states
   (not started, in progress, completed, malformed) so every badge and status is visible.
3. For `dashboard.png`: open the **Kiro Spec Tracker** view from the activity bar, make sure
   a few specs are present, then capture the view panel.
4. For `explorer-decorations.png`: expand `.kiro/specs/` in the Explorer and capture the
   tree with the badges visible.

## Conventions

- Format: PNG, lossless.
- Width: 1200–1600 px; crop tightly to the relevant panel, no full desktop.
- Theme: use the default dark theme for the primary shots (most common on marketplaces).
- Keep the files small (ideally under ~300 KB each) so the README stays light.
- Do not include personal or sensitive paths/content in the capture.

## Animated demo (optional)

A short animated demo can be added later for the dashboard flow (open, search, toggle
layout). Keep it under ~3 MB and ~10 s. Prefer hosting it as a GitHub release asset or via
`user-images.githubusercontent.com` and linking it from the README, rather than committing
a large binary into the repository history.
